# product-sort — Proposal

## 流程 profile

- **选择**：standard
- **选择理由**：单一商品域（specs 域数 = 1），不改数据模型；但属于跨前后端联动的新功能（列表接口新增排序行为 + 首页新增排序交互），按 4 步判定法 Step 3 命中 standard。

## 为什么做

买家目前只能按固定顺序浏览商品列表，找便宜商品或新上架商品要逐条翻。提供排序能力可以让用户按自己关心的维度快速定位商品，是电商列表页的基础体验。

## 做什么

1. 用户在首页商品列表可以选择排序方式：价格从低到高、价格从高到低、最新上架
2. 选择后列表立即按所选方式重新排列
3. 用户刷新页面或把地址分享给别人时，排序选择保持不变（体现在页面地址中）
4. 不选择任何排序时，列表保持现有的默认顺序

## 不做什么

- 不做多字段组合排序（如"先价格再时间"）
- 不做按销量/评分排序（当前商品没有这些信息）
- 不改变商品搜索行为
- 不做管理员侧的排序配置

## 对现有能力的影响

- 商品域（products）：「商品列表浏览」能力增强，新增排序行为；其余能力不变
- 用户域：无影响

## 用户交互流程

主流程：打开首页 → 在列表上方的排序选择器选"价格从低到高" → 列表按价格升序重排 → 刷新页面排序保持。
异常流程：地址中带了无法识别的排序值 → 列表按默认顺序展示，不报错、不白屏。

## 数据模型预期

无需新增需要记住的信息；排序只是浏览时的展示方式。

## 验收标准（人话版）

1. 三种排序方式各自生效：价格升序时第一件是全场最便宜的；价格降序时第一件是最贵的；最新上架时第一件是最近创建的
2. 排序选择体现在页面地址中，刷新后保持
3. 地址中的排序值不合法时，页面正常展示默认顺序，无错误提示
4. 不影响现有的商品详情跳转

## 风险与待确认项

- 无未决口径；排序仅作用于当前返回的全部商品（本项目列表无分页）

## 方案提示（可选）

无特殊要求，遵循现有架构模式即可。
