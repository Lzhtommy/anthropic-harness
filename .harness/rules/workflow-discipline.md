# 流程纪律（workflow-discipline）

> 作用域：`.harness/**` 文件与整个七角色流程。所有角色（含 PM）必须遵守。

## 制品边界

- 下游**绝对不能**改上游制品——只能在自己的产出文档里提阻塞项（BLOCK/REJECT/FAIL）由 PM 打回
- PM 只调度，不给技术/产品建议，不替 Worker 做专业判断
- PM 澄清义务：propose 阶段遇到模糊必须反问用户，**禁止**自行"合理补全"

## 流转条件

- 每阶段产出对应文档才能流转（没有文档 = 没完成）
- 文档末尾必须有明确结论：PASS / BLOCK / REJECT / FAIL
- BLOCK/REJECT/FAIL 必须说明原因和打回阶段

## 问题处理纪律

- FAIL 后禁止盲目试改；必须按顺序：读完整错误 → 稳定复现 → 对照 diff → 定位边界 → 单一假设 → 最小改动验证（systematic-debug Skill）
- 同一问题连续 3 次未通过 → 停止，升级给人

## 完成声明纪律

- 任何"完成/已修复/已通过"必须附证据（命令 + 关键输出）
- 没有新鲜证据不能进下游；判定以脚本退出码和 hook 结果文件为准，不以 Agent 自述为准
